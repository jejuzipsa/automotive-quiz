# PC·모바일 학습 기록 동기화 설계 — 제안 (미구현)

## 현재 구조

GitHub Pages 정적 사이트. 문제은행은 공개 정적 JSON이며 학습 기록은 브라우저 localStorage에만 존재한다. GitHub Pages 자체에는 사용자별 쓰기 가능한 데이터베이스나 인증 API가 없다. 기존 기록은 변경하지 않는다.

## 권장 구조

정적 프런트엔드는 그대로 유지하고 선택적 로그인 + 별도 인증/DB 서비스를 추가하는 방안을 우선 검토한다. 예: Supabase Auth/Postgres 또는 Firebase Auth/Firestore. 제공자 선택, 계정 연결, 비용 및 지역 설정은 사용자 승인 후 결정한다. 서비스 키/개인 기록을 공개 GitHub 저장소나 정적 JS에 넣지 않는다. 공개 클라이언트 키 사용 시 서버 측 사용자별 접근 규칙 필수.

## 동기화 대상

| 데이터 | 동기화 정책 |
|---|---|
| 일반 문제/기출 문제 정답·오답·미응답 | 문항 ID 및 내용 버전, 개별 학습 이벤트 ID로 중복 제거. 구 과목/참고 정답 통계는 분리 |
| 문제 출제 로테이션 | 사용자·과목별 대기열 및 사이클 버전, 동시 시작 충돌 처리 |
| 핵심 단어 카드 | 카드 ID별 중요/외움 상태 및 갱신 시각 |
| 한손노트 | 과목별 페이지/개념 ID 및 갱신 시각 |
| 글자 크기·테마 | 기기별 설정 유지 또는 사용자 선택 |
| 진행 중 시험 | 2차 단계. 절대 마감 시각·답안·문항 버전 검증, 동시 기기 편집 방지 |

## 구현 순서

1. 실제 저장 키/스키마 전수 목록화, 버전형 내보내기/가져오기 및 복구 테스트부터 제공. 개인 데이터만 포함하고 문제 원문/비밀정보 제외. 손상 입력 검증, 용량 제한, 덮어쓰기 전 백업.
2. 기존 localStorage 스냅샷을 최초 로그인 때 한 번만 가져오는 마이그레이션. 기존 누적 카운터는 과거 이벤트 재구성 불가하므로 기준 스냅샷으로 저장하고 기기별 카운터를 단순 합산하지 않는다.
3. 신규 답안은 고유 이벤트 ID를 사용해 오프라인 큐에 기록하고 서버에서 멱등 처리. 사용자별 RLS/보안 규칙, 다른 사용자 읽기/쓰기 거부를 자동 검사.
4. 카드/진도 등의 상태는 변경 시각 및 버전 기반 충돌 정책, 서버 확인 이후 동기화 상태 표시.
5. 시험 진행 기록은 마지막 단계. 기기 전환 후에도 마감 시각을 연장하지 않으며 기기별 시험 잠금/충돌 처리 및 기록 손실 방지 테스트.
6. iOS Safari·Android Chrome·PC Chrome/Edge·Mac Safari, 오프라인/복귀/동시 로그인/삭제/로그아웃/기존 데이터 마이그레이션 검사.

## 완료 기준 및 제약

다른 기기에서 동일 계정으로 학습 이력이 일치하고, 같은 이벤트 재전송으로 오답률이 중복 집계되지 않으며, 다른 사용자 접근이 차단된다. 계정 삭제/데이터 내보내기 및 로컬 사용 모드를 제공한다. 본 문서는 설계이며 인증·백엔드 생성·데이터 전송·자동 동기화는 아직 수행하지 않았다.
