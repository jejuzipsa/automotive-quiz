# 문제 검수 절차 — 20문항 단위

## **QA8 텍스트 은행 운영 원칙 (이전 이미지 출제 안내보다 우선)**

1. **최종 출제 형식은 텍스트**. 이미지 원본은 OCR 오류를 찾아내는 비공개 검수 증거로만 사용한다. `question`, `choices[4]`, `answer`(원본 순서 1~4), `explanation`, 과목·회차·검수 상태를 JSON에 보존한다.
2. **보기 섞기는 JSON 저장 시점이 아니라 매회 출제 시점**에 수행한다. 원본 정답의 `originalIndex`와 표시 번호를 매핑하여 정답 번호를 매번 새로 계산한다. 오답 재풀이도 다시 섞는다.
3. QA8 현재 수치: 720문항 텍스트 구조 있음 / 원문대조 25 / 미검수 OCR 695 / 기술 정답 승인 0. **미검수 OCR을 정답 확정으로 표시하지 않는다.**
4. 단계별 검수: (a) 원본 스크린샷과 텍스트 전체 대조 (b) 정답·해설의 자동차 정비 기술적 근거 확인 (c) 중복·조건/부정형·수치 점검 (d) 대외 게시 권한. 서로 별도 체크.
5. **공개 GitHub Pages에 구매 교재 원문/해설을 배포하지 않는다.** QA8 ZIP/JSON을 본인이 홈페이지에서 불러오면 브라우저 IndexedDB에만 저장. 파일을 영구 공개하려면 게시 권리와 서버 측 접근제어를 먼저 확보해야 한다.
6. 다음 검수 시작점: `auto-r01-s02-q01` (1회 섀시정비 1번). 검수 20문항 단위마다 개인 ZIP 새 버전·SHA256·WORK_LOG·HANDOFF·bank-status 갱신.
7. 구현 참고: `gichul-quiz/app.js`의 `buildSessionItem`, `correctDisplayIndices`, `shuffle`; 자동차정비 구현 `quiz-utils.js`, `personal-text-bank.js`.
8. 실제 PNG·스캔이 별도 이미지 첨부가 없어도 문항 성립이 가능할 때만 텍스트 출제 승인. 회로 그림이 정답에 꼭 필요하면 대체 가능한 표현의 정확성을 검증할 때까지 보류.

## 단계 0 — 원본과 버전 식별
1. 개인 파일 라이브러리에서 QA6 ZIP을 불러오고 `docs/HANDOFF.md`의 SHA256과 일치하는지 확인.
2. `bank.json`의 문항 ID와 `questions/`, `explanations/` 이미지 경로가 일치하는지 확인.
3. `ocr-candidates.json`은 **초안**일 뿐. QA1~QA5 텍스트를 원본 대신 사용하지 말 것.

## 단계 1 — 정확한 원문 전사
- 단위: `r01-s01-q01`~`q20`, 다음 `r01-s02` 순으로 20개씩.
- 원본 문제 그림을 직접 보고 지문과 선택지 4개를 전사/대조.
- 기술 약어(ECU, MAF, ABS, CAN 등), 수치, 단위, 부정형(옳지 않은 것), 문장부호/보기 번호를 특별 점검.
- 글자 오인식 추정으로 임의의 정답/조건을 만들어 넣지 말 것. 원본이 모호하면 보류.
- 회로도·그림이 정답에 중요하면 이미지 필드를 필수로 유지.
- 원본 해설 이미지 대조 후 `source_text_checked=true` + 검수 일시/근거(이미지 파일/좌표)를 기록.
- 해설을 억지로 매끈하게 고치는 것은 **전사와 별도 편집 작업**으로 표시.

## 단계 2 — 정답과 내용의 기술 검증
- 원본 정답표 번호와 보기의 의미가 맞는지 비교.
- 제조사 정비 매뉴얼, 출제기준, 신뢰 가능한 자동차 기술자료를 근거로 검증.
- '가장 먼저', '반드시', '표준값', 전압·압력·저항 등은 제조사/차종/조건 확인.
- 안전절차(SRS, 고전압차)와 복수 오답/복수 정답은 고위험 보류.
- `technical_checked=true`는 **명시적 근거와 날짜가 있을 때만** 설정.
- 정답표에 그렇게 적혀 있다는 이유만으로 정답 기술검증 완료 처리하지 않는다.

## 단계 3 — 중복 검증
- 지문·선택지가 완전히 동일한 경우만 후보 확정 후 병합, 출처 및 이전 ID 보존.
- 선택지 순서만 다르면 정답 번호 재매핑 확인.
- 지문은 비슷하지만 '옳은/옳지 않은', 측정 조건/차종/이상 증상이 다르면 독립 유지.
- 중복 후보는 QA6 기준 2쌍, 과거 QA5까지 확장 16쌍(다른 알고리즘 결과). 같은 기준 수치가 아니라서 확정 중복 건수로 보고하지 않는다.

## 단계 4 — 사용 권한/게시
- 스캔·구매 교재의 사적 학습 범위와 공공 웹 게시 권한은 별개.
- `rights_cleared=true` 확인 전에는 어떤 상업 원문·해설도 공개 Pages에 등록하지 않음.
- 법적으로 이용 가능한 경우에만 `publishable=true` 적용. 모든 조건을 AND로 묶어 배포.
- 공개 GitHub 저장소/Pages에 업로드한 JSON·이미지는 외부에서 다운로드 가능함.
- 별도 비공개 학습용 호스팅은 **서버 측 인증과 파일 접근 통제**가 있어야 함.

## 제출/인계 규칙
20문항 처리마다 반드시 다음을 업데이트:
1. `docs/WORK_LOG.md`: 번호 범위·수정 이력·근거 링크·검증 미완료 이유.
2. `data/bank-status.json`: 구조/전사/기술검증 수치.
3. `docs/HANDOFF.md`: 다음 처리할 문항 ID, 교정본 SHA256, 아직 남은 오류.
4. 개인 자료 ZIP은 **별도 백업**; 공개 저장소에는 저작물 원문 미포함.
